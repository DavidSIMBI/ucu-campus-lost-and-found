# Team workflow

This is a shared group project foundation. Keep changes small enough for teammates to review and explain.

## Suggested workflow

1. Agree on the task and expected behavior before editing shared files.
2. Create a focused branch for each piece of work and avoid committing generated files or `.env` files.
3. Keep frontend screens, API routes, database changes, and documentation aligned. Update the relevant README or design note when a setup step changes.
4. Use fictional data in screenshots, demonstrations, and seed scripts. Never use real student passwords, contact details, or ownership evidence.
5. Review teammates’ changes for correctness, readability, and privacy before merging them into the group branch.
6. Before presenting, follow the root README setup steps and manually check the pages and `GET /api/health`.

## Team coordination

Record task owners, decisions, and meeting notes in the shared project workspace. When changing a database table or API response, tell the teammates working on the other layer and document the change so they can adapt their work.

## Before a team change is complete

- Confirm the change matches the agreed project requirements.
- Check that no secrets or personal data were added.
- Explain how the feature or setup can be demonstrated to the group.
- Update documentation when another teammate would otherwise have to guess how to use it.
